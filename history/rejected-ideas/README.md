# Rejected ideas (in-development)

**Purpose:** ideas proposed *during* development that the team decided not
to build, with the reason, so nobody re-proposes and re-litigates them
mid-hackathon. For the pre-development research-phase rejections (datasets
ignored, stack options not chosen, hard "no touch" categories), see
`research/rejected-ideas/README.md` instead — that one is the inherited
baseline from the initial planning pack; this one is for anything rejected
after the bootstrap, during actual build.

**What goes here:** short entries — idea, who proposed it, why rejected,
date. A few sentences is enough; this is not an ADR.

**What does not go here:** decisions that were actually adopted (→
`DECISIONS.md` + `history/decisions/`), or research-phase rejections
already covered in `research/rejected-ideas/`.

**Depends on:** none.
