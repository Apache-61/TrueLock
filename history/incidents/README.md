# Incidents

**Purpose:** record anything that broke the demo path, leaked a credential,
produced a wrong forensic conclusion presented as fact, or otherwise
needed an unplanned fix — so the same mistake isn't repeated by a
different worker.

**What goes here:** one `YYYY-MM-DD-short-slug.md` per incident: what
happened, detection, impact, root cause, fix, follow-up task ID if one was
created.

**What does not go here:** routine bugs tracked as normal `type:bug`
tasks/issues — this is for things that actually broke something (main,
the demo, a security property), not for the everyday backlog.

**Depends on:** none. Referenced from `SECURITY.md` if security-relevant.
